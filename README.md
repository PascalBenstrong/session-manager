# Session Manager

A browser extension (Firefox and Chrome) that tracks tabs in sessions, lets you search and organize them, and cleans cookies and site data. It is written in Rust with an [egui](https://github.com/emilk/egui) UI, compiled to WebAssembly. See [spec.md](spec.md) for the requirements.

## Layout

| Path | Contents |
|------|----------|
| `src/` | **Shared Rust code.** The core (`model`, `search`, `organize`, `workspace`, `tab_strip`, `guards`, `media`, `hibernate`, `cleanup`, `pattern`, `state`, `protocol`, `url`) is plain Rust and unit-tested natively. `background.rs`, `platform.rs` and `ui/` build only for wasm. |
| `web/` | Shared pages and loaders: `popup.html`, `manager.html`, `sidebar.html` (sidebar / side panel), `inspector.html` (inspector window), `background.js`, `ui.js`, `platform-common.js` (the default `smPlatform` JS shim), `media.js` (content script for the media limit and the stream controls, registered only while one of them is on), `inspect.js` (inspector content script), `capture.html` / `capture-engine.js` / `capture-page.js` (capture window, its engine, and the capture content script) and `guards/` (page guard scripts). |
| `icons/` | Shared icons, generated by `tools/gen-icons.mjs`. |
| `firefox/` | Firefox-only files: `manifest.json` and `platform.js` (overrides: creating tabs already discarded, site-data removal by `hostnames`). |
| `chrome/` | Chrome-only files: `manifest.json` (MV3 service worker) and `platform.js` (site-data removal by `origins`). |
| `CHANGELOG.md` | Release notes, compiled into the extension and shown on its *What's new* page. |
| `spec.md` | What the extension does (requirements). |
| `tools/` | Smoke test, mock browser API, in-browser preview, icon generator. |

The Rust code reaches the browser only through `globalThis.smPlatform`. To support another browser, add a folder with a `manifest.json` and a `platform.js` that calls `installPlatform(api, overrides)`.

## Build

Requirements:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129 --locked   # must match Cargo.lock
```

Then run:

```sh
./build.sh                 # dist/firefox and dist/chrome (release build)
./build.sh firefox         # one browser only
PROFILE=dev ./build.sh     # faster, unoptimized build
```

If `wasm-opt` (binaryen) is installed, `build.sh` runs it to shrink the wasm file further.

## Install in your browser

You don't need Node or a server. Build once with `./build.sh`, then load the `dist/` folder:

**Chrome / Edge / Brave** (stays installed):
1. Open `chrome://extensions` (`edge://extensions` in Edge).
2. Turn on **Developer mode**.
3. Click **Load unpacked** and select the `dist/chrome` folder.
4. Pin it: click the puzzle-piece icon in the toolbar, then the pin next to *Session Manager*.

**Firefox, for development** (removed when Firefox restarts):
1. Open `about:debugging#/runtime/this-firefox`.
2. Click **Load Temporary Add-on…** and select `dist/firefox/manifest.json`.
3. In `about:addons` → *Session Manager* → *Permissions*, allow **Access your data for all websites**. Cookie clean-up needs it.

**Firefox, permanently:** run `./build.sh --zip` to create `dist/session-manager-firefox.zip`, then either:
- Firefox Developer Edition / Nightly / ESR: set `xpinstall.signatures.required` to `false` in `about:config`, then *about:addons* → ⚙ → **Install Add-on From File…** → pick the zip.
- Regular Firefox: the add-on must be signed. Upload the zip as an *unlisted* add-on at addons.mozilla.org (or use `web-ext sign`), then install the signed `.xpi` it gives you.

After rebuilding, reload the extension: the ⟳ button on `chrome://extensions`, or **Reload** in `about:debugging`.

## Using it

- **Toolbar popup (quick switcher):** click the toolbar icon or press **Alt+Shift+S**. Type to search the current session (the same search syntax as below; toggle *All sessions* to widen it), use **↑/↓** to move, and **Enter** or a click to jump to the tab; the popup closes. **Esc** closes it. The header has the session picker, *Last tab*, *Load*, and the session menu. **Open manager ⛶** opens the full page.
- **Change the shortcut:** `chrome://extensions/shortcuts`, or *about:addons* → ⚙ → *Manage Extension Shortcuts* in Firefox.
- **Full manager page:** sidebar with all sessions, plus the Tabs, Organize, Snapshots & import, Cookies & data and Settings views.
- **Snapshots, saving & importing:** open *Snapshots & import* in the manager, or choose *💾 Snapshots, save & import…* from the "⋯" session menu (the popup opens the manager for this, since file pickers close extension popups). *📸 Save snapshot* in that menu saves a revision right away.

## Releasing

1. Add a `## [x.y.z] - YYYY-MM-DD` entry at the top of [CHANGELOG.md](CHANGELOG.md), with `### New` / `### Improved` / `### Fixed` sections and `- ` bullets.
2. Set the same version in `Cargo.toml`, `firefox/manifest.json` and `chrome/manifest.json`. `cargo test` fails if any of them disagree.
3. Run `./build.sh --zip`.

When users get the update, the toolbar icon shows **NEW** and the popup highlights *What's new* until the notes have been opened.

## Tests

```sh
cargo test                                         # core unit tests (native)
./build.sh && node tools/smoke-test.mjs firefox    # real wasm background against a mock browser API
node tools/smoke-test.mjs chrome
node tools/serve.mjs   # then open http://127.0.0.1:8123/tools/preview.html (add ?popup for popup size)
# with the server running:
node tools/real-browser-test.mjs edge      # real, visible Edge with the developer tools open
node tools/real-browser-test.mjs firefox   # real, visible Firefox with the developer tools open
```

`tools/capture-test.mjs` (Edge; with `tools/serve.mjs` running) records the videos of `tools/real/media.html` (top frame and a frame), records the tab cut to a video, saves an HLS and a DASH stream through the capture window's own controls, and saves and uploads the results.

`tools/guards-test.html` runs the page guards against hostile page code in any browser (`?control` runs it without them). `tools/real-browser-test.mjs` loads the built extension into a throwaway profile, browses the hostile test site in `tools/real/` with the developer tools open, and checks the guards, ad-tab rules and inspector with real clicks: first without guards (the page must win), then with them.

The preview runs the real background and UI together in a normal page, using seeded mock tabs and workspaces. `?popup` uses the popup size, `?sidebar` the sidebar page, `?inspector&tab=1` the inspector (inspecting the preview page itself), `?compact` / `?group=Domain` set the tab list look, `#backup` (or another view name) opens that view, `?click=x,y;x,y` / `?hover=x,y` / `?keys=ArrowDown,Enter` simulate input, and `?clip=text` stands in for the clipboard in headless screenshots.

The UI has dark and light themes; the toggle in the header cycles System → Light → Dark and is remembered.

## Features

**Sessions**
- Opened tabs are added to the *active* session automatically. Browser-internal pages are ignored (configurable).
- Closing a tab removes it from its session. When a whole window closes, or the browser quits, its tabs are kept as *unloaded* entries instead (configurable).
- *Set active* switches the session that new tabs go to without opening any of its tabs.
- *Load* opens a session's closed tabs: unloaded/lazy, in a new window, or fully loaded.
- *Last tab* focuses the session's most recently used tab, reopening it if needed.
- You can remove a tab from its session manually; it stays open but is no longer tracked. You can also close it, or move it to another session.
- On startup, tabs are re-linked to their entries by tab ID, then by URL.

**Workspaces**
- Group tabs into workspaces, each with a name, color and icon. Workspaces are shared by all sessions. The Tabs view lists tabs under colored workspace headers, with a *No workspace* section for the rest.
- **Click a workspace's header** to open its settings: rename it, pick an icon and color, edit its rules, search in it, hibernate its tabs, reorder it, or delete it (its tabs are kept). The ▾ arrow folds the section.
- **Open a workspace's saved tabs:** ⤓ on a workspace header (shown on hover; in the sidebar too, with *Saved*) opens the closed tabs listed under it, and *⤓ Open its closed tabs* in its settings opens all of them in the session. They open unloaded and in the background, in their workspace, and load when you select them.
- **Select several tabs:** tick their boxes, Ctrl-click, Shift-click for a range, Ctrl+A (Esc clears), or ☑ on a workspace header. A bar at the bottom moves them to a workspace or out of theirs, opens the closed ones unloaded, hibernates, tags, groups, moves them to another session, stops tracking or closes them. Drag a selected tab onto a workspace to move them all.
- **Move tabs** by dragging them onto a workspace header, with *Workspace* in a tab's ✏ editor, or with *Workspace ▾* in the bulk bar for every search match.
- **Rules** add tabs automatically when they open, navigate, or get a group or tag:
  - *Site*: domain, exact host, URL prefix, glob or regex.
  - *Added to group*: the extension's group or a native browser tab group with that name.
  - *Has tag*.
  - *Matches search*: any search, e.g. `title:invoice -host:mail.example.com`.

  The first workspace with a matching rule wins (reorder workspaces to change that). Rules never take a tab out of a workspace, and don't touch tabs you placed by hand; choose *Let the rules decide* to undo that.
- **Search** across all workspaces (the default), only some (*In: workspaces* in the search options ⚙, or *Search in this workspace*), or with `ws:name` in the query.

**Workspaces in the browser** (Settings → *Workspaces in the browser*)
- **As tab groups:** each workspace's tabs sit in a native tab group titled with its icon and name, in its color (Chrome, Edge, Firefox 139+). Drag a tab into a workspace's group to move it there, or out of the group to take it out. *Collapse the other workspaces* collapses the other groups when you switch workspaces; a group you expand stays open.
- **Current workspace:** the workspace of the tab you use. Switch with the pills in the sidebar, ⇄ on a workspace header, or *Switch to it* in its settings. Optionally, new tabs join it.
- **Sidebar:** Firefox's sidebar or Chrome's side panel shows the window's tabs by workspace, with a workspace switcher, ＋ new tab per workspace, drag and drop, and (with *Saved*) the session's closed tabs. On a tab, ◌ takes it out of its workspace, 💾 closes it but keeps it saved, 🗙 closes and removes it, 🗑 deletes a saved one, and ⏸ stops its stream; right-click for these and to move it to another workspace. Open it with **Alt+Shift+W**, ◨ in the popup, or the button in Settings.
- **Hide other workspaces (Firefox):** only the current workspace's tabs (plus pinned tabs and tabs without a workspace) stay in the tab bar. Firefox asks for the "Hide and show browser tabs" permission when you turn it on. Optionally the window title starts with the workspace.
- **Hide Firefox's tab bar:** Settings has a step-by-step userChrome.css guide. It names the preference to set in `about:config` (`toolkit.legacyUserProfileCustomizations.stylesheets` → `true`), tells you where the file goes, and lets you copy or download the stylesheet. Firefox doesn't let extensions open `about:config` / `about:support`, so their buttons copy the address when the page can't be opened.

**Page guards** (the 🛡 view; they run in pages before the pages' own scripts; reload open pages after changing them)
- **Pop-ups & ad tabs:** *Block pop-ups that weren't asked for* stops windows and tabs opened without a click, or by code that catches clicks anywhere on the page (pop-under ads). Links you click still work.
- **Custom rules:**
  - *Block script* `ads.example.com`, `*popunder*.js` or `/regex/`, optionally only on some sites. The script never loads.
  - *Close tabs opened to* `adserver.com`: such tabs are closed at once and you're back on the page.
  - *Block all pop-ups on* `example.com`.

  *Tabs opened by pages* lists recent ones with one-click rules, the inspector's Media & frames has ⛔ Block on each script, and its Ads view blocks whole ad networks.
- **Play-button hijacks:** *Stop ads that hijack the play button* stops clicks on a video player (or on an invisible layer over the page) from opening windows or tabs, and switches off a layer laid over the player so the click reaches it.
- **Right-click & copying:** pages can't block the context menu (and, optionally, selecting and copying).
- **Developer tools:** *Remove debugger traps* (runtime-built `debugger` statements; in Firefox also those in script files), *Hide the developer tools from pages* (window size, shortcuts), and *Silence the page's console* (console-based detection).
- **Open frame in new tab:** right-click any iframe or frame in a page.
- **Exceptions:** sites where no guard runs, e.g. web apps with their own context menus.

**Inspector** (Alt+Shift+I, 🔬 in the popup or on a tab row, or Page guards → Inspector): inspects a page without the browser's developer tools, so pages can't detect it. It opens docked at the bottom of the page, or in its own window (⬓ / 🗗 switch, and the choice sticks; drag the dock's top edge to resize it).
- **Elements:** 🎯 pick an element in the page, browse the DOM tree, find by CSS selector, and see the path, selector, size, attributes, computed style, text and HTML. The tree is live (it follows changes to the page) and the selected element stays highlighted on the page. Right-click an element for copy options (HTML, text, page selection, selector, JS path, XPath, attributes, styles), to open a frame in a new tab, take a screenshot (save or copy), scroll to it or delete it.
- **Network:** ● Record (it goes on when the page reloads, from each page's first request; ⟳ Reload and record also catches the current page from its start) lists fetch, XHR, WebSocket (connections and messages) and beacon requests with headers, bodies, responses, timing and initiator. ▶ Replay one (right-click or the details) or ▶ Replay all those listed, with a pause between them: XHRs go through the page's own handlers again, received WebSocket messages are delivered to the page again, sent ones and fetch / beacon requests are sent again. Copy as cURL or fetch(). The log keeps every page's requests, marked by page; those of earlier pages can be sent again from what was recorded.
- **Throttling** (Network view, bottom bar): hold back every request, or those matching a pattern (right-click a request: *this request*, *requests like this*, or edit the rule first; or ＋ New rule), by a delay. A rule applies to the current tab only, unless kept for every tab of the site; ✏ edits pattern, method, delay and scope. Rules cover every request type and stay on across reloads. Chrome does it through its debugger (a permission the extension asks for at install; Chrome does not allow it to be optional) and shows a "debugging this browser" bar while a throttled page is open.
- **Network settings** (⚙): delay of new rules, pause between replays, scope of new rules, start recording when the view opens, keep the log across reloads.
- **Reloads:** the inspector doesn't restart. A window keeps the page shown until the new one is read and selects the same element again; a docked inspector comes back as soon as the page starts loading, where it was (view, selection, recording, log).
- **Ads:** the ad networks the page runs, from the scripts, frames, requests and ad slots of all its frames, the ad tags written into its own code (inline and encoded), and the tabs it opened, with rules to block a network on the site or everywhere.
- **Media & frames:** video, audio, source, subtitle, poster, iframe, frame, embed, object and script URLs of the page and all its frames, plus media requests (the real stream URLs behind `blob:` videos). Grouped by type and searchable; copy, open, or ⛔ block a script.
- **Capture:** the video and audio elements of the page and its frames, and the streams and media files it loads. *● Record* opens a capture window recording the element's own stream (picture and sound, picture only or sound only; WebM, or MP4 in Chromium), or what the browser shows of it (*Rendered on screen*: you pick the tab once, and only the video's area is kept). *⬇ Save…* opens a stream (HLS `.m3u8`, DASH `.mpd`) or file to save it as it is: choose the quality and the sound track; picture and sound kept apart by the stream become separate files. *Open a media URL* does the same for any address. The capture window plays what it captures (live while recording), saves it, uploads it (PUT / POST, raw or as a form field, custom headers), and plays it on another sound output or in picture-in-picture. The view lists open capture windows, and can stop them. Protected (DRM) media isn't captured: browsers black it out, and encrypted streams aren't saved.
- **Source:** the page as it is now, with line numbers and search.

**Hibernate** (the 💤 menu above the list, or 💤 on a row or workspace header)
- Unload tabs to free memory; they stay in the tab strip and reload when selected. Choose all browser tabs, this session's tabs, the tabs matching the search, or tabs not used for 15 minutes, an hour, a day or a week (or search `idle:2h` for any duration).
- Active tabs are never hibernated. Pinned tabs and tabs playing media are skipped unless you choose *Force hibernate all tabs*.

**Media limit** (Settings → *Media playback*)
- *Only in the active tab*: background tabs that start playing video are paused.
- *Limit background tabs*: at most N background tabs play besides the active one(s). The least recently used are paused first.
- Paused media resumes when you switch back to its tab. Options: include audio-only media, and keep picture-in-picture videos playing.

**Performance** (Settings → *Performance*): switches for the features that work in every page or on every tab change: stream controls, replay of stopped streams, media limit, page guards (all off at once), workspaces as tab groups.

**Stopped streams** (to save data)
- Live streams only (normal videos are left alone). ⏸ *Stop stream* on a playing live video (shown on hover), or the player's own pause button, next to its tab in the sidebar and the popup, or in the tab's menu: its videos pause and its media data (stream manifests and segments, media files) is held back until you resume it. ⏸ in the sidebar's footer stops every background tab's streams.
- Firefox holds the requests (the player just waits); Chrome blocks them (session rules), and reloads the page if the player doesn't recover on resume. Live streams resume at their live edge. The page can't play a stopped video by itself; the player's own play button resumes it.
- Optional replay (Settings → *Stopped streams*): a low-resolution loop of the video's last frames over it while stopped, from memory.

**Tab list look** (the *View* menu above the list): group by workspace, domain, host, group, tag or nothing; compact one-line rows; show or hide tag and group chips. The choice is saved.

**Search** (tooltip on the search box): `host:` `domain:` `tag:` `group:` `ws:` `title:` `url:` fields; `=exact` / `^exact$`, `^prefix`, `suffix$`, `*glob?`, `/regex/`, and `-negation`; `is:open|unloaded|hibernated|playing|pinned|grouped|ungrouped|tagged|duplicate`; `idle:30m` (also `s`, `h`, `d`, `w`, `mo`, `y`); and time filters on when a tab was last used, added, opened, closed, loaded or unloaded: `used:` `added:` `opened:` `closed:` `loaded:` `unloaded:` with `2h` / `<2h` (within the last 2 hours), `>1w` (over a week ago), `1d..1w`, `today` `yesterday` `week` `lastweek` `month` `lastmonth` `year` `lastyear`, dates (`2026-11-01`, `2026-11`, `2026`, with `<` `<=` `>` `>=`) and ranges (`2026-11-01..2026-11-05`, `2026-11..`). Dates are in local time and weeks start on Monday. You can also set the default field and match mode, case sensitivity, workspace and group filters, and search all sessions. Bulk actions (tag/untag, set group, set workspace, hibernate, move, remove, close) apply to every match.

**Organize**
- Group the list by domain, host, group or tag.
- Re-order the browser's tabs by any of those keys, optionally as native tab groups (Chrome, and Firefox versions that expose `tabGroups`).
- Optionally re-organize automatically whenever tabs change (debounced).
- Auto rules add tags and a group to tabs whose URL matches a pattern.

**Duplicate tabs**
- **Where:** Organize → *Duplicate tabs*, the "⧉ N duplicates" badge in the Tabs view, or *⧉ Remove duplicates* in the "⋯" session menu (also in the popup).
- **What counts as the same page:** you choose which differences to ignore: `#fragment` and trailing `/` are ignored by default; `?query`, `www.` and http vs https are optional.
- **Which copy stays:** the open one, then the one in the active session, then the most recently used. Tags of the removed copies are merged into it, and their group too if the kept copy has none. Extra open tabs are closed, unless you choose to leave them open and only remove them from the session.
- **Scope:** the current session or all sessions. Search `is:duplicate` to list them first.
- **Prevent duplicates (opt-in):** opening a page that's already in the active session switches to the existing tab and closes the new one. If the saved copy is unloaded, the new tab simply takes its place. Tabs the extension opens itself (loading or restoring a session) are never affected.

**Snapshots (revisions)**
- Save the current tab list of a session as a named snapshot. Each snapshot shows how it differs from now (`+added / −removed`).
- Restore a snapshot in one of three ways:
  - **Replace:** the current list is snapshotted first, so this can be undone. Open tabs that are in the snapshot stay linked; other open tabs stay open but are no longer tracked.
  - **Add missing tabs:** only the snapshot's tabs that aren't in the session yet.
  - **Open as a new session.**
- Restored tabs can optionally be opened right away, unloaded.
- Optional automatic snapshots every N minutes. These only happen for sessions that changed. Only the last N automatic snapshots are kept; manual ones are never pruned.

**Saving to disk and importing**
- Download one session or all sessions as `.json` (optionally with snapshots), a single snapshot, or the URL list as `.txt` (comma separated). *Copy URLs* puts that list on the clipboard.
- Import from a file (*Open file…* or drag-and-drop onto the page), from the clipboard, or by pasting into the text box.
  - **Session files** become new sessions; nothing is overwritten.
  - **URL lists:** URLs can be separated by commas, newlines, spaces or semicolons, and may be enclosed in single or double quotes, so a quoted URL keeps its commas and separators (`"https://example.com/?ids=1,2"`). Bare hosts like `example.com/x` get `https://`, duplicates and non-URLs are skipped. Choose to add them to the current session or a new one, and whether to open them unloaded right away.
  - **CSV / TSV:** a file with a header row is read as a table; pick the column that holds the URLs (each column shows how many URLs it has, and the best one is chosen first). Quoted fields, commas inside them and semicolon- or tab-separated files work.

**Cookies and site data**
- Clean cookies, cache, local & session storage, IndexedDB and service workers for:
  - the current tab's whole site (with its subdomains): one click on *🧹 Clear this site's data* in the popup
  - a host, domain (including subdomains), URL prefix, glob or regex
  - all open tabs
  - all domains
- Manual clean-ups also clear storage from inside the open tabs of the sites cleaned (all frames). This reaches session storage, `window.name` and embedded frames' partitioned storage, which `browsingData` can't. A partitioned cookie goes with the site it was set under. Cleaning a site from the popup first stops its tabs from saving, then reloads them, so a page can't write back what it holds in memory.
- A *keep* list protects domains from cleaning.
- Saved rules can run on a timer (`alarms`) and/or delete matching cookies as soon as a site sets them.
- A log records recent clean-ups.

## Known limitations

- **Per-site cache (Firefox):** Firefox can't clear the HTTP cache for individual sites. Per-site clean-ups there skip the cache and show a warning; *All domains* clears the whole cache.
- **"Clean whenever a new value is set":** only cookies can be watched, through `cookies.onChanged`. Other storage has no change events that extensions can observe.
- **Domain grouping:** the domain is a heuristic "registrable domain" (it handles `co.uk`-style suffixes) rather than the full Public Suffix List.
- **Chrome tab loading:** Chrome can't create tabs that are already discarded, so "unloaded" tabs are created and then discarded right away. They may start loading briefly.
- **Clipboard permission:** *Paste from clipboard* uses the `clipboardRead` permission (shown at install as "read data you copy and paste"). Pasting with Ctrl+V into the import box works without it.
- **Media limit and stream controls:** they use a content script (`media.js`), registered while one of them is on; it only runs in pages loaded after that (reload older tabs), and not in browser-internal pages. Muted videos smaller than 640×360 (hover previews) are left alone.
- **Hibernating:** browsers refuse to unload the active tab. Chrome may give a hibernated tab a new id; the extension follows it.
- **Debugger traps in Chrome:** Chrome doesn't let extensions change scripts, so `debugger` statements written in script files stay. Use the developer tools' *Deactivate breakpoints* (Ctrl+F8). Firefox removes them.
- **Capture:** recording runs in real time (a stream can be saved faster). *Rendered on screen* needs a tab to be shared: Firefox shares windows and screens, not tabs, so there the whole window is recorded, without its sound. A video inside a frame inside another frame is recorded with the whole tab. Saved streams keep the picture and sound that the stream keeps apart as separate files (no muxing). Live streams are saved as far as they're listed when you start.
- **Guards and the inspector** don't run on browser-internal pages or extension stores. The inspector's element tree covers the top frame.
- **Ad detection** is a heuristic: networks are recognised from their hosts, tag paths and the names in the page's own code. A network that serves everything from an unnamed, changing domain is listed by that domain (as a possible ad host) rather than by name, and ads that load after the page does show up after ⟳ Refresh in the Ads view.
- **Tab bar:** extensions can't restyle or replace the browser's tab bar. Workspaces show up there as native tab groups, or (Firefox) by hiding the other workspaces' tabs; hiding Firefox's own tab bar needs the userChrome.css you install yourself. Chrome can't hide tabs.
- **Bundle size:** the wasm file is about 6 MB, mostly egui and its fonts. The background and UI share the same module.
